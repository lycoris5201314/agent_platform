# Agent Foundry

**Windows 本地 AI Agent 工作台：连续对话、文件操作、多任务并行，以及可跨重启恢复的长期任务。**

Agent Foundry 复用开源 **Codex App Server** 执行模型对话与工具调用，在外层实现桌面界面、任务调度、SQLite 数据保存和恢复机制。支持 OpenAI、本项目适配的 DeepSeek 模型，以及满足协议要求的自定义模型服务。

这是独立开发的软件，不是 OpenAI 官方 Codex 客户端，也不等同于官方桌面应用的全部功能。当前定位是 **本机单用户**，多用户和多租户保留后端接口。

## 1. 安装与第一次使用

1. 打开 [最新 Release](https://github.com/lycoris5201314/agent_platform/releases/latest)，在 **Assets** 下载 `Agent-Foundry-Setup-<版本>-x64.exe`。
2. 双击安装，选择安装位置，然后从桌面或开始菜单打开 **Agent Foundry**。
3. 打开左下角 **设置与运行时 → 模型连接**，在对应服务商下填写 API Key，点击 **保存 Key**。修改 Base URL、默认模型或兼容选项后，再保存设置。
4. 点击 **新建对话**，选择工作文件夹和已配置模型，输入任务并发送。
5. 在同一对话底部继续追问；结束后查看回复、**本轮变更**和产物文件。

仓库已公开，下载无需 GitHub 令牌。未签名的自建安装包可能触发 Windows SmartScreen 提示；请核对来源和 Release 提供的 SHA-256。

**不需要预先安装 Codex、Node.js、WSL2、Ubuntu 或 Docker。** Setup 携带桌面运行环境与 Codex 可执行文件。当前发布目标为 Windows x64；执行某个具体项目时，仍可能需要该项目使用的 Git、Python、Node.js 等工具。Git worktree 和 Git 操作需要 Git，WSL2、Docker 仅在主动选择对应后端时需要。

只发布 **Setup 安装版**。`Source code.zip` / `tar.gz` 是开发源码，不能替代安装包；开发目录中的 `release/Agent Foundry/` 是构建验收产物，不是另一套 Portable 发布。

可以先发送：

没有 Key 时可用 **Mock 演示**检查界面和任务流程。Mock 不调用真实模型，不能用于评价回答质量。

## 2. 实现了哪些 Codex 类似功能

以下依据本仓库代码整理。“复用”指调用内置 Codex App Server；“平台实现”指 Agent Foundry 自己的界面或业务逻辑。具体能力受模型服务商和内置运行时版本影响。

| 功能 | 本软件的实现和入口 |
| --- | --- |
| 连续对话与恢复 | 复用 Thread / Turn；同一对话连续布置任务，退出后保存历史并继续 |
| 文件读写与命令执行 | 复用 Codex 工具能力，在所选工作区读取、修改文件和执行命令 |
| 可见的执行过程 | 展示关键命令、工具状态、错误、验证和公开推理摘要；合并重复增量，不展示私有原始思维链 |
| 模型与推理深度 | 输入框下方选择已配置模型，空闲时调整下一轮设置；实际推理档位取决于模型支持 |
| 沙箱与审批 | 只读、工作区写入、完全访问；按策略询问，由用户批准或自动风险审查 |
| 停止与补充指令 | 停止按钮中断；有活动回合时补充指令，没有活动回合时作为下一轮发送 |
| 编辑上条消息 | 最近一条用户消息可撤回到输入框修改后重发；不会自动撤销已写入磁盘的文件 |
| 对话分支 | 复用历史和 rollout，可选择共享工作区或独立 worktree；显示分支来源，不伪造用户指令 |
| 子 Agent 与并行任务 | 委派子任务并传递父任务上下文、子任务身份；支持独立 worktree、结果查看和合并审批 |
| 上下文压缩 | 显示压缩状态；第三方不兼容时提供本机摘要恢复路径，见记忆说明 |
| 审阅和差异 | 工作区审阅、逐文件 diff、行级意见、暂存/取消暂存及丢弃审批 |
| Skills、MCP、插件 | 能力中心查看、启停、重载、授权连接和插件市场管理 |
| 对话管理 | 按工作文件夹分组、搜索、置顶、归档和恢复；分支保持项目归属 |
| 桌面交互 | Markdown、图片拖放/粘贴、文件选择、侧栏宽度调整、终端和快捷命令 |

官方 [Codex App Server 文档](https://learn.chatgpt.com/docs/app-server) 定义了线程、回合、审批和事件等嵌入接口。本项目使用随软件打包的运行时，不保证覆盖官方最新客户端的全部接口和功能。

## 3. 平台额外实现了什么

“额外”指本项目在执行内核外自行实现的部分，不表示官方 Codex 永远没有类似能力。

| 平台扩展 | 作用 |
| --- | --- |
| 持久化等待 `durable_wait` | 保存等待原因、到期时间和恢复点，释放 Worker|
| 外部信号等待 | 完成时间未知时等待外部系统通知，收到持久信号后继续 |
| 持续目标 | 明确上报进度后自动续跑；支持轮次、截止时间、Token 预算、暂停、恢复和结束 |
| SQLite 调度和恢复 | 队列、租约/心跳、并发限制、重试退避、死信、重启恢复 |
| 每轮快照与产物汇总 | 展示本轮前后新增、修改、删除，避免混入工作区长期未提交变更 |
| 全库搜索与历史导航 | 查询完整历史，按需加载旧轮次，悬停预览、点击跳转 |
| 可移动输入框、多窗口 | 拖动底部输入框并一键复位；对话拖出主窗口，多任务同时操作 |
| 加密草稿、密钥与备份 | Windows 当前用户加密；数据库健康检查、一致性备份和恢复 |
| 问题反馈资料 | 导出对话、事件和脱敏日志，辅助复现故障 |
| Windows 集成 | 托盘、提醒、防休眠、窗口恢复及持续交互 PowerShell |

## 4. 配置模型和 API Key

推荐使用 **设置与运行时 → 模型连接**：

- **OpenAI**：填写 API Key，账号需有对应模型权限；可用目录来自运行时。
- **DeepSeek**：本版适配配置为 `https://api.deepseek.com` 和 `deepseek-v4-flash`，仍需账号与服务端提供对应 Responses 能力。
- **自定义服务**：需兼容 **Responses API、流式事件和工具调用**。只有 Chat Completions 接口，或只是持有某厂商 Key，不足以接入当前执行流程。

模型下拉框列出已配置且标记为 Responses/Codex 兼容的服务；第三方使用已保存的默认模型。兼容选项是配置声明，不会自动转换不兼容协议。图片理解、推理档位也取决于模型。

界面保存的 Key 使用 Windows DPAPI 加密，API 不回传明文；**模型调用费用由对应服务商收取**。

### 配置文件方式

应用菜单 **Agent Foundry → 编辑 API Key 配置** 会打开实际使用的 `agent.env`。通常在 EXE 旁，安装目录不可写时回退到当前用户应用数据目录。优先通过菜单打开，避免修改错文件。

```dotenv
# DeepSeek
DEEPSEEK_API_KEY=填写你的密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash

# OpenAI（也可只配置这一组）
OPENAI_API_KEY=填写你的密钥
OPENAI_MODEL=填写账号可用的模型名称

# 自定义 Responses 服务（可选）
MODEL_API_KEY=
MODEL_BASE_URL=
MODEL_NAME=
MODEL_WIRE_API=responses
```

只填写需要的服务，其他 Key 留空。保存后桌面版重新加载连接；正在执行的回合沿用启动时的配置。`agent.env` 中的 Key 是明文，日常使用优先选择界面加密保存。不要把真实 Key 放进 GitHub、安装包或反馈资料。

## 5. 日常使用

### 对话、文件和窗口

- 新建先打开**临时草稿**，第一次发送才创建任务；Esc 或“稍后继续”保留，“丢弃草稿”清空。
- **工作区**通过磁盘选择器指定。右侧“浏览磁盘”可进入其他目录，再“设为当前工作区”；运行或等待中的任务需先结束/停止。
- **文件栏**可编辑文本、预览 PDF 和常见图片，其他格式用“系统打开”；不是完整的 Word / Excel 编辑器。
- **本轮变更**展示最近一轮变化，产物卡打开生成文件；二进制文件通常没有文本行数。
- **历史导航**在长对话右侧：悬停预览，点击定位；旧记录按需补载，“回到最新”返回底部。
- **底部输入框**上沿“按住拖动输入框”可移动，“恢复底部位置”复位；切换对话也会复位。
- **多窗口**可将左侧对话拖到窗口外，或点击“弹出窗口”；“放回主窗口”收回。实际并发由 Worker 和 Provider 设置控制。

**对话上下文独立，不等于磁盘文件独立。** 两个对话使用同一工作区时都能看到其中的文件。需要隔离修改时，选择不同文件夹或独立 worktree；worktree 要求 Git 仓库至少有一次提交。

### 权限选择

| 设置 | 含义 |
| --- | --- |
| 只读 | 以读取和分析为主，写入受限 |
| 工作区写入 | 允许在任务工作区范围内修改，适合日常任务 |
| 完全访问 | 放宽执行限制，命令可能影响更大的本机范围 |
| 请求批准 / 非可信操作询问 | 按策略等待审批决定 |
| 帮我批准 | 使用自动风险审查，不表示所有请求都会获准 |
| 无需批准 | 不弹出审批请求；与沙箱范围是不同设置 |

文件栏是用户主动浏览磁盘的入口，浏览目录本身不自动授予模型写权限。Docker bridge 模式目前没有将模型通信和工具网络完全拆分隔离。

### 快捷操作

| 快捷键或命令 | 用途 |
| --- | --- |
| Enter / Shift + Enter | 发送 / 换行 |
| Ctrl + N / Ctrl + K | 新建 / 全局搜索 |
| Ctrl + B / Ctrl + Alt + U | 右侧工作区 / 活动任务 |
| 输入 `/` | 快捷命令菜单 |
| `/files`、`/changes`、`/terminal` | 文件、变更、终端 |
| `/compact`、`/fork`、`/review`、`/delegate` | 压缩、分支、审阅、委派 |
| `/stop`、`/goals`、`/automations` | 停止、持续目标、自动化 |

菜单只显示当前状态可用的操作。

## 6. 长任务如何等待和继续

**模型实际调用平台工具才会触发持久化等待**，普通命令中的 `sleep` 不会自动转换。可以这样要求：

> 结果未就绪时，使用 durable_wait 等待 60 秒后重新检查，不要长时间执行 sleep；就绪后汇总。

1. 调用 `durable_wait(seconds, reason)`，单次 1 秒至 24 小时。
2. 平台保存恢复点、到期时间，标记等待并释放 Worker 名额。
3. 到期后调度继续；工具会话仍有效时直接恢复，否则在恢复上下文中重新检查实际结果。
4. 未就绪可再次等待，完成后验证并结束；用户可停止任务。

未知完成时间使用 `wait_for_external_signal`；外部系统通过 `POST /api/signals/:key/resolve` 通知。需要外部系统接入，不会自行监控任意网站。

**持续目标**只有在模型明确上报继续、无阻塞、且未达轮次/时间/Token 上限时才续排。Token 按回合结束核算，不是达到某个 Token 就立即硬中断。**自动化**则按时间表创建独立对话。

关闭窗口后托盘可继续运行；**完全退出、关机或系统睡眠期间不执行任务**。重启后才检查到期等待和错过的计划；错过的自动化合并补运行一次。

## 7. 记忆、数据位置和备份

### 分层记忆

完整聊天记录保存在数据库；模型运行时有当前上下文；平台另维护摘要和相关记忆用于恢复。默认只检索当前对话，分支或委派按明确关系传递历史。

压缩会损失细节，不等于永远记住全部原文。第三方压缩不兼容时，本机回退用摘要建立新的执行线程，聊天历史仍保留；Token 或压缩比例可能是估算。重要要求建议保存到工作区文件。

### 保存位置

以 **设置与运行时 → 数据与更新 → 保存位置** 为准，也可使用应用菜单“打开数据目录”。

| 内容 | 默认位置或方式 |
| --- | --- |
| 桌面版数据库 | `%APPDATA%/agent-foundry-local/data/agent-platform.db` |
| 自动工作区 | 数据目录下 `workspaces/<任务 ID>` |
| 手动工作区 | 你选择的原目录，归档不会删除工作文件 |
| 备份 / 加密草稿 | 数据目录下 `backups/` / `ui/` |
| 反馈资料 | 数据目录下 `问题反馈资料/` |
| 源码开发模式 | 项目下 `.agent-data/`，可由环境变量调整 |

在实际使用的 `agent.env` 中设置自定义目录：

```dotenv
AGENT_DATA_DIR=E:/AgentFoundryData
```

随后从托盘完全退出并重启。已有用户应先退出、备份并复制原数据目录的完整内容到新位置，再修改配置；这不是运行中自动迁移。记录中的原工作区绝对路径不会自动改写，原文件夹需继续可访问。

设置页可创建一致性数据库备份，以及校验、恢复并重启。数据库备份**不含工作区文件、附件正文或完整运行时目录**。换电脑需另复制工作文件；Windows 加密的 Key 和草稿通常不能跨电脑/用户解密，需要重新配置。

归档只是收起对话；永久删除需要明确确认，并受子任务与依赖等条件限制。

## 9. 当前边界

- 单用户本地优先；鉴权、RBAC、租户隔离、审计和配额接口不等于已完成公网多用户 SaaS。
- 不提供官方 Codex 全部账号、云任务、跨设备同步或专有服务，不自动读取官方客户端对话。
- 默认关闭内置 Web Search；外部系统和联网能力需要相应工具、MCP 与权限。填写 Key 不会自动获得浏览器或办公应用控制能力。
- 插件和 MCP 受内置协议、外部依赖和授权影响；Docker 的本机 OAuth 回调尚有限制。
- 自动验证只覆盖可识别/已配置的检查，不能替代业务结果和文档内容验收。
- 公开推理摘要、图片、压缩、模型目录随 Provider 而异；网络、权限、余额或配额仍可能导致失败。

## 10. 开发与架构

主要通过 **Codex App Server 双向 JSON-RPC** 接入执行内核，没有用 OpenAI Agents SDK Runner 作为平台调度器。

```text
Electron + React 桌面界面
          ↓ 消息、配置、审批
Fastify 本机 API ↔ SQLite 对话、事件、队列、记忆
          ↓
Task Runner → Codex App Server → 模型服务 / 工具
          ↓
工作区 → 本轮差异与产物 → 验证 → 返回或继续
```

源码开发需要 Node.js 22.13+（CI 使用 Node 24），Windows 原生为默认后端：

```powershell
git clone https://github.com/lycoris5201314/agent_platform.git
cd agent_platform
npm ci
Copy-Item .env.example .env
npm run dev
```

仅首次创建 `.env`，不要覆盖已有配置。模板默认 `AGENT_RUNTIME=mock`，真实运行改为 `codex` 并配置服务。开发 Web 默认 `http://localhost:3000`，API 默认 `http://localhost:8788`，以启动输出为准。

桌面版自行启动 Web/API，使用随机的 `127.0.0.1` 端口，无需用户开命令窗口；托盘退出后释放。

```powershell
npm test                    # 源码、构建、协议和发布流程检查
npm run desktop:window-smoke # 真实桌面交互验收
npm run desktop:dist        # 构建 Setup 与本机验收目录
npm run release:verify      # 完整发布前验收，先退出应用
```

完整发布验收包含真实模型任务，需要兼容 Key 和网络，不能把 Mock 成功当作真实模型成功。构建会更新 `release/Agent Foundry/` 并保留已有 `agent.env`。

| 目录 | 作用 |
| --- | --- |
| `app/` | 对话、工作区、设置、目标和自动化界面 |
| `desktop/` | 窗口、托盘、配置、草稿、更新、诊断 |
| `server/core/` | 类型、配置、SQLite、状态机、事件、工具网关 |
| `server/runtime/` | Codex / Mock、Provider、MCP 和插件控制 |
| `server/workflow/` | 调度、等待恢复、验证闭环、委派 |
| `server/workspace/`、`server/sandbox/` | Windows / WSL2 工作区与 Docker 生命周期 |
| `server/terminal/`、`server/security/` | 交互终端、身份和加密密钥 |
| `server/verification/`、`tests/` | 项目检查、协议、安装和发布验收 |
| `.github/workflows/` | 干净 Windows 环境构建发布 |

推送与包版本一致的 `vX.Y.Z` 标签后，Actions 先测试，再构建、启动解压版、全新安装并启动 Setup，全部通过才发布安装包、校验文件和更新元数据。**本地通过不代替云端通过；发布后还应重新下载正式资产验证。**

## 11. 常见问题

**没有 Codex 能运行吗？** 可以，安装包已内置。具体任务使用的开发工具仍可能需要安装。

**没有可用模型？** 检查 Key、默认模型、Responses 兼容配置、账号权限和网络，并确认修改的是实际使用的配置文件。

**关闭窗口为什么仍在运行？** 关闭窗口保留托盘，托盘“退出”才停止服务。

**其他对话为什么看到相同文件？** 上下文独立，但相同工作区的磁盘内容共享。

**worktree 为什么要求 commit？** 它基于 Git 已有提交创建。先初始化并提交基线，或使用普通/共享工作区。

**能只把 EXE 发给别人吗？** 应发送完整 Setup。安装目录的主 EXE 依赖旁边资源，不能单独拎出。

**所有电脑、模型都保证可用吗？** 发布验收覆盖指定 Windows x64 环境、运行时和交互场景；实际模型还受服务端能力、网络、Key 和任务所需工具影响。
